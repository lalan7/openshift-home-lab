    Bucket Information¶

    # View your bucket details
oc get obc test-rgw-bucket -n app-fullstack

# Bucket name (auto-generated)
oc get configmap test-rgw-bucket -n app-fullstack -o jsonpath='{.data.BUCKET_NAME}'
# Output: test-rgw-bucket-ac74616f-7536-4c7d-8bf2-534c33977107

# S3 Endpoint (internal)
oc get configmap test-rgw-bucket -n app-fullstack -o jsonpath='{.data.BUCKET_HOST}'
# Output: rook-ceph-rgw-ocs-storagecluster-cephobjectstore.openshift-storage.svc

# Port
oc get configmap test-rgw-bucket -n app-fullstack -o jsonpath='{.data.BUCKET_PORT}'
# Output: 443 (HTTPS with self-signed cert)

    Access Credentials¶

    # Access Key ID
oc get secret test-rgw-bucket -n app-fullstack \
  -o jsonpath='{.data.AWS_ACCESS_KEY_ID}' | base64 -d

# Secret Access Key
oc get secret test-rgw-bucket -n app-fullstack \
  -o jsonpath='{.data.AWS_SECRET_ACCESS_KEY}' | base64 -d

    Where is the Data Stored?¶

    Important: The data is NOT stored in the pod filesystem!

    • Data is stored in Ceph RGW (RADOS Gateway) object storage backend
    • RGW stores objects in Ceph RADOS pools (distributed across OSDs)
    • The pod only accesses data via S3 API calls
    • Data persists even if the pod is deleted
    • Data is replicated according to Ceph pool replication settings

    How to Use RGW S3 Storage¶

    Method 1: Use the Test Pod (Already Configured)¶

    # Exec into the test pod
oc exec -it test-rgw -n app-fullstack -- bash

# Environment variables are already set:
# - AWS_ACCESS_KEY_ID
# - AWS_SECRET_ACCESS_KEY
# - S3_BUCKET
# - S3_ENDPOINT

# List files
aws s3 ls s3://$S3_BUCKET/ \
  --endpoint-url https://$S3_ENDPOINT \
  --no-verify-ssl

# Upload a file
echo "My data" > /tmp/myfile.txt
aws s3 cp /tmp/myfile.txt s3://$S3_BUCKET/ \
  --endpoint-url https://$S3_ENDPOINT \
  --no-verify-ssl

# Download a file
aws s3 cp s3://$S3_BUCKET/myfile.txt /tmp/downloaded.txt \
  --endpoint-url https://$S3_ENDPOINT \
  --no-verify-ssl

# Delete a file
aws s3 rm s3://$S3_BUCKET/myfile.txt \
  --endpoint-url https://$S3_ENDPOINT \
  --no-verify-ssl

    Method 2: Create Your Own Application with S3 Access¶

    apiVersion: v1
kind: Pod
metadata:
  name: my-s3-app
  namespace: app-fullstack
spec:
  containers:
  - name: app
    image: my-app-image
    env:
    # Load credentials from the Secret
    - name: AWS_ACCESS_KEY_ID
      valueFrom:
        secretKeyRef:
          name: test-rgw-bucket
          key: AWS_ACCESS_KEY_ID
    - name: AWS_SECRET_ACCESS_KEY
      valueFrom:
        secretKeyRef:
          name: test-rgw-bucket
          key: AWS_SECRET_ACCESS_KEY
    # Load config from the ConfigMap
    - name: S3_BUCKET
      valueFrom:
        configMapKeyRef:
          name: test-rgw-bucket
          key: BUCKET_NAME
    - name: S3_ENDPOINT
      valueFrom:
        configMapKeyRef:
          name: test-rgw-bucket
          key: BUCKET_HOST
    - name: S3_PORT
      valueFrom:
        configMapKeyRef:
          name: test-rgw-bucket
          key: BUCKET_PORT

    Method 3: Mount Credentials as Files¶

    apiVersion: v1
kind: Pod
metadata:
  name: my-s3-app
  namespace: app-fullstack
spec:
  containers:
  - name: app
    image: my-app-image
    volumeMounts:
    - name: s3-credentials
      mountPath: /s3-credentials
      readOnly: true
    - name: s3-config
      mountPath: /s3-config
      readOnly: true
  volumes:
  - name: s3-credentials
    secret:
      secretName: test-rgw-bucket
  - name: s3-config
    configMap:
      name: test-rgw-bucket

    Then in your application: 

    export AWS_ACCESS_KEY_ID=$(cat /s3-credentials/AWS_ACCESS_KEY_ID)
export AWS_SECRET_ACCESS_KEY=$(cat /s3-credentials/AWS_SECRET_ACCESS_KEY)
export S3_BUCKET=$(cat /s3-config/BUCKET_NAME)
export S3_ENDPOINT=$(cat /s3-config/BUCKET_HOST)

    Create Additional Buckets¶

    apiVersion: objectbucket.io/v1alpha1
kind: ObjectBucketClaim
metadata:
  name: my-new-bucket
  namespace: my-namespace
spec:
  generateBucketName: my-new-bucket
  storageClassName: ocs-storagecluster-ceph-rgw

    This will automatically create: - A new S3 bucket - A Secret: my-new-bucket (with credentials) - A ConfigMap: my-new-bucket (with bucket name and endpoint)

    Using S3 from Outside the Cluster¶

    To access RGW from outside OpenShift, you need to expose it via a Route:

    # Check if RGW route exists
oc get route -n openshift-storage | grep rgw

# If not, create one:
oc create route edge rgw-external \
  --service=rook-ceph-rgw-ocs-storagecluster-cephobjectstore \
  --port=http \
  -n openshift-storage

# Get the external URL
oc get route rgw-external -n openshift-storage -o jsonpath='{.spec.host}'

    Then use the external hostname as your S3 endpoint.

    Troubleshooting¶

    Connection Issues¶

    If you get "Connection was closed" errors: - Use HTTPS instead of HTTP: --endpoint-url https://... - Add --no-verify-ssl flag (self-signed cert)

    Slow Performance¶

    RGW performance depends on: - Underlying Ceph OSD performance - Network latency - Object size (smaller objects = more overhead)

    Check RGW Pods¶

    # Check RGW pods
oc get pods -n openshift-storage | grep rgw

# Check RGW logs
oc logs -n openshift-storage -l app=rook-ceph-rgw --tail=50
