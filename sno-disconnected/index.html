    SNO Disconnected Test Environment¶

    Purpose: Test oc-mirror and OSUS workflows in an isolated disconnected environment
    Created: December 2025
    Environment: homelab-server.example.com (kcli/libvirt)

    Architecture¶

    homelab-server.example.com (192.0.2.107)
├── Management Cluster (untouched)
│   └── 6 VMs on br-hypershift (192.168.125.x)
│
└── SNO Test Environment (sno-test network: 198.51.100.0/24, ISOLATED)
    │
    │  ⚠️  ISOLATED NETWORK - NO INTERNET ACCESS FOR VMs
    │
    ├── mirror-registry VM (198.51.100.141)
    │   ├── 2 vCPU, 6GB RAM, 200GB disk
    │   ├── Quay-based registry on port 8443
    │   └── ❌ NO internet access (truly isolated)
    │
    └── sno-disconnected VM (198.51.100.60)
        ├── 8 vCPU, 16GB RAM, 120GB disk
        ├── Single Node OpenShift 4.20.8 (upgraded from 4.18.14)
        └── ❌ NO internet access (truly isolated)

    homelab-server can reach both VMs via bridge (198.51.100.1)

    Prerequisites¶

    • Access to homelab-server.example.com via SSH
    • Red Hat pull-secret (saved in pull-secret.json)
    • kcli installed on homelab-server

    Step-by-Step Deployment¶

    Phase 1: Create Isolated Network¶

    # SSH to homelab-server
ssh lab-user@homelab-server.example.com

# Create ISOLATED network for SNO test (--isolated = NO NAT, NO INTERNET)
kcli create network -c 198.51.100.0/24 --domain example.local --isolated sno-test

# Verify network is isolated (should NOT show 'nat')
kcli list network | grep sno-test
# Expected: sno-test | routed | 198.51.100.0/24 | True | example.local | isolated

# Add DNS entries for mirror-registry and SNO
sudo virsh net-update sno-test add dns-host \
  "<host ip=\"198.51.100.141\">
    <hostname>mirror-registry.example.local</hostname>
    <hostname>mirror-registry</hostname>
  </host>" --live --config

sudo virsh net-update sno-test add dns-host \
  "<host ip=\"198.51.100.60\">
    <hostname>sno-disconnected.example.local</hostname>
    <hostname>api.sno-disconnected.example.local</hostname>
    <hostname>api-int.sno-disconnected.example.local</hostname>
  </host>" --live --config

# Verify network
kcli list network

    Phase 2: Create Mirror Registry VM¶

    # Use 6GB RAM (4GB causes memory pressure during large mirror operations)
kcli create vm \
  -P numcpus=2 \
  -P memory=6144 \
  -P disks=[150] \
  -P nets=[sno-test] \
  -P image=centos9stream \
  mirror-registry

# Wait for IP assignment
sleep 30
MIRROR_IP=$(kcli info vm mirror-registry -f ip -v)
echo "Mirror Registry IP: ${MIRROR_IP}"

    Phase 3: Install mirror-registry Tool¶

    # SSH to mirror-registry VM
kcli ssh mirror-registry

# Install podman
sudo dnf install -y podman

# Download mirror-registry tool
curl -L -o mirror-registry.tar.gz \
  https://mirror.openshift.com/pub/openshift-v4/clients/mirror-registry/1.3.11/mirror-registry.tar.gz
tar -xzf mirror-registry.tar.gz

# Fix cgroup configuration (required for VMs)
sudo mkdir -p /etc/containers/containers.conf.d
cat << 'EOF' | sudo tee /etc/containers/containers.conf.d/cgroups.conf
[engine]
cgroup_manager = "cgroupfs"
EOF

# Install mirror-registry (save the password!)
sudo ./mirror-registry install \
  --quayHostname mirror-registry.example.local \
  --quayRoot /opt/quay

# IMPORTANT: Configure Quay for OCP mirroring
cat << 'EOF' | sudo tee -a /opt/quay/quay-config/config.yaml

# Allow large OCP image layers (default 5MB causes 413 errors)
MAXIMUM_LAYER_SIZE: 20G

# Enable automatic pruning of old tags
FEATURE_AUTO_PRUNE: true
EOF

# Restart Quay to apply the changes
sudo podman restart quay-app quay-postgres quay-redis
sleep 30

# Verify registry is working
curl -sk https://localhost:8443/v2/_catalog

exit

    Note: - MAXIMUM_LAYER_SIZE: 20G - Required for OCP image layers (default 5MB causes HTTP 413 errors) - FEATURE_AUTO_PRUNE: true - Enables automatic cleanup of old image tags

    Phase 4: Configure homelab-server for oc-mirror¶

    # On homelab-server
mkdir -p ~/oc-mirror-workspace

# Add registry to /etc/hosts
echo "198.51.100.141 mirror-registry.example.local" | sudo tee -a /etc/hosts

# Get CA certificate from mirror-registry
kcli ssh mirror-registry "sudo cat /opt/quay/quay-rootCA/rootCA.pem" \
  > ~/oc-mirror-workspace/mirror-registry-ca.pem

# Add CA to system trust
sudo cp ~/oc-mirror-workspace/mirror-registry-ca.pem /etc/pki/ca-trust/source/anchors/
sudo update-ca-trust

    Phase 5: Install oc-mirror and openshift-install¶

    # Download oc-mirror
curl -sL https://mirror.openshift.com/pub/openshift-v4/x86_64/clients/ocp/stable/oc-mirror.tar.gz \
  -o /tmp/oc-mirror.tar.gz
tar -xzf /tmp/oc-mirror.tar.gz -C /tmp
sudo mv /tmp/oc-mirror /usr/local/bin/
sudo chmod +x /usr/local/bin/oc-mirror

# Install nmstate (required for agent config validation)
sudo dnf install -y nmstate

    Phase 6: Create Combined Pull-Secret¶

    cd ~/oc-mirror-workspace

# Copy your Red Hat pull-secret to pull-secret-rh.json
# Then add mirror-registry credentials:
MIRROR_PASSWORD="<your-mirror-registry-password>"
MIRROR_AUTH=$(echo -n "init:${MIRROR_PASSWORD}" | base64 -w0)

jq --arg auth "$MIRROR_AUTH" \
  '.auths += {"mirror-registry.example.local:8443": {"auth": $auth}}' \
  pull-secret-rh.json > pull-secret.json

    Phase 7: Create ImageSetConfiguration¶

    cat > ~/oc-mirror-workspace/imageset-config.yaml << 'EOF'
apiVersion: mirror.openshift.io/v2alpha1
kind: ImageSetConfiguration
mirror:
  platform:
    architectures:
      - amd64
    channels:
      - name: stable-4.18
        minVersion: 4.18.14
        maxVersion: 4.18.14
    graph: true

  operators:
    - catalog: registry.redhat.io/redhat/redhat-operator-index:v4.18
      packages:
        - name: cincinnati-operator
          channels:
            - name: v1
EOF

    Phase 8: Run oc-mirror¶

    cd ~/oc-mirror-workspace

oc mirror --v2 \
  --config imageset-config.yaml \
  docker://mirror-registry.example.local:8443/ocp4 \
  --workspace file://./workspace \
  --authfile pull-secret.json

# Verify generated resources
ls -la workspace/working-dir/cluster-resources/

    Generated files: - idms-oc-mirror.yaml - ImageDigestMirrorSet - itms-oc-mirror.yaml - ImageTagMirrorSet
    - cs-redhat-operator-index-v4-18.yaml - CatalogSource - updateService.yaml - OSUS UpdateService config

    Phase 9: Extract openshift-install from Mirrored Release¶

    # Extract tools from mirrored release (ensures version match)
mkdir -p /tmp/ocp-tools
oc adm release extract \
  --tools \
  --from=mirror-registry.example.local:8443/ocp4/openshift/release-images:4.18.14-x86_64 \
  --to=/tmp/ocp-tools \
  --registry-config=/home/lab-user/oc-mirror-workspace/pull-secret.json

# Install openshift-install
cd /tmp/ocp-tools
tar -xzf openshift-install-linux-4.18.14.tar.gz
sudo mv openshift-install /usr/local/bin/

    Phase 10: Create SNO Installation Configs¶

    mkdir -p ~/sno-disconnected
cd ~/sno-disconnected

# Create install-config.yaml
cat > install-config.yaml << 'EOF'
apiVersion: v1
baseDomain: example.local
metadata:
  name: sno-disconnected
networking:
  networkType: OVNKubernetes
  clusterNetwork:
  - cidr: 10.128.0.0/14
    hostPrefix: 23
  serviceNetwork:
  - 172.30.0.0/16
  machineNetwork:
  - cidr: 198.51.100.0/24
compute:
- name: worker
  replicas: 0
controlPlane:
  name: master
  replicas: 1
platform:
  none: {}
pullSecret: '<PULL_SECRET_JSON_INLINE>'
sshKey: '<SSH_PUBLIC_KEY>'
imageDigestSources:
- mirrors:
  - mirror-registry.example.local:8443/ocp4/openshift/release
  source: quay.io/openshift-release-dev/ocp-v4.0-art-dev
- mirrors:
  - mirror-registry.example.local:8443/ocp4/openshift/release-images
  source: quay.io/openshift-release-dev/ocp-release
additionalTrustBundle: |
  <MIRROR_REGISTRY_CA_CERT>
EOF

# Create agent-config.yaml
cat > agent-config.yaml << 'EOF'
apiVersion: v1alpha1
kind: AgentConfig
metadata:
  name: sno-disconnected
rendezvousIP: 198.51.100.60
hosts:
- hostname: sno-disconnected
  role: master
  interfaces:
  - name: enp1s0
    macAddress: 52:54:00:aa:bb:60
  networkConfig:
    interfaces:
    - name: enp1s0
      type: ethernet
      state: up
      ipv4:
        enabled: true
        address:
        - ip: 198.51.100.60
          prefix-length: 24
        dhcp: false
    dns-resolver:
      config:
        server:
        - 198.51.100.1
    routes:
      config:
      - destination: 0.0.0.0/0
        next-hop-address: 198.51.100.1
        next-hop-interface: enp1s0
EOF

    Phase 11: Generate Agent ISO¶

    cd ~/sno-disconnected
openshift-install agent create image --dir=. --log-level=info

# Copy ISO to libvirt images directory
sudo cp agent.x86_64.iso /var/lib/libvirt/images/sno-agent.iso

    Phase 12: Create and Boot SNO VM¶

    # Create VM with ISO
kcli create vm \
  -P numcpus=8 \
  -P memory=16384 \
  -P disks=[120] \

    413 Request Entity Too Large During Mirroring¶

    Symptom: 

    StatusCode: 413, "<html><head><title>413 Request Entity Too Large</title></head>..."
[Worker] error mirroring image ... uploading layer chunked: StatusCode: 413

    Technical Explanation¶

    Quay Architecture:

    ┌─────────────────────────────────────────────────────────────┐
│                    Quay Container (quay-app)                │
│                                                             │
│   ┌──────────┐    ┌─────────────────┐    ┌──────────────┐  │
│   │  nginx   │───►│  gunicorn-web   │    │  PostgreSQL  │  │
│   │  :8443   │    │  (API/UI)       │    │  (metadata)  │  │
│   │          │───►│                 │    └──────────────┘  │
│   │          │    │ gunicorn-       │    ┌──────────────┐  │
│   │          │───►│ registry        │───►│  /datastorage│  │
│   │          │    │ (blob uploads)  │    │  (images)    │  │
│   └──────────┘    └─────────────────┘    └──────────────┘  │
└─────────────────────────────────────────────────────────────┘

    The Problem:

    1. nginx sits in front of all Quay endpoints
    2. nginx has client_max_body_size limits in /conf/nginx/nginx.conf
    3. Default limit: 5MB for general requests
    4. OCP image layers can be 100MB - 500MB+ each
    5. When oc-mirror uploads a layer > 5MB, nginx rejects it with HTTP 413

    nginx Config Locations:

    /conf/nginx/nginx.conf           → client_max_body_size 5M;    (global default)
/conf/nginx/server-base.conf     → client_max_body_size 5M;    (general endpoints)
                                 → client_max_body_size 20G;   (blob upload endpoints)

    The Issue:

    The server-base.conf has 20GB limits for blob endpoints, but only if MAXIMUM_LAYER_SIZE is set in Quay's config. Without this setting, the config template uses the 5MB default.

    Config Template Logic:

    # /conf/nginx/server-base.conf.jnj (Jinja2 template)
location /v2/ {
    client_max_body_size {{ maximum_layer_size }};  # Uses MAXIMUM_LAYER_SIZE from config
}

    If MAXIMUM_LAYER_SIZE is not set → defaults to 5MB → 413 errors.

    Solution¶

    # SSH to mirror-registry
kcli ssh mirror-registry

# Add MAXIMUM_LAYER_SIZE to Quay config
echo "MAXIMUM_LAYER_SIZE: 20G" | sudo tee -a /opt/quay/quay-config/config.yaml

# Restart Quay containers to regenerate nginx config
sudo podman restart quay-app quay-postgres quay-redis

# Wait for startup (~30-60 seconds)
sleep 60

# Verify registry is working
curl -sk https://localhost:8443/v2/_catalog

# Verify nginx config was updated
sudo podman exec quay-app grep "client_max_body_size" /conf/nginx/server-base.conf
# Should show: client_max_body_size 20G;

exit

    Why This Happens with OCP Images¶

    Image Type Typical Layer Size Affected by 5MB limit?
    Alpine/busybox 2-5 MB No
    Standard app 10-50 MB Yes
    OCP component 50-200 MB Yes
    OCP release payload 100-500 MB Yes

    OCP releases contain large base images (RHEL UBI, Go binaries, etc.) that easily exceed 5MB.

    Prevention¶

    Add MAXIMUM_LAYER_SIZE: 20G during initial mirror-registry installation (see Phase 3).

    Recommended Quay config additions for OCP mirroring:

    # /opt/quay/quay-config/config.yaml
MAXIMUM_LAYER_SIZE: 20G           # Allow large OCP image layers
FEATURE_PROXY_STORAGE: true       # Enable storage proxy (optional)
CREATE_NAMESPACE_ON_PUSH: true    # Auto-create namespaces (already default)

    Mirror Registry Storage Management¶

    Understanding Shared Image Layers¶

    OpenShift releases use content-addressable storage with SHA256 digests. This means:

    4.18.14 ──┐
4.18.30 ──┼──> etcd:sha256:abc123, kube-apiserver:sha256:def456, ...
4.19.20 ──┤    (same underlying images shared across versions!)
4.19.21 ──┘

    Key insight: Minor versions (4.18 → 4.19) share ~80-90% of container images because: - Most Kubernetes components remain the same - Only version-specific components differ - Blobs are deduplicated by SHA256 digest

    Expected Storage Usage¶

    Content Approximate Size
    1 OCP version 50-70 GB
    2 OCP versions (4.18 + 4.19) 80-100 GB (shared layers)
    3 OCP versions 100-120 GB
    + Operators (5-10) +20-40 GB

    Cleanup Reality¶

    When you "delete" old version tags:

    Action What Happens Space Freed
    Delete 4.18.x tags Tag references removed Minimal
    Keep 4.19.x only Shared blobs still needed ~5-10%
    Delete ALL old versions Orphan blobs can be GC'd Variable

    Why? Deleting a tag doesn't delete the underlying blobs if ANY other tag references them.

    Using the Prune Script¶

    cd ~/oc-mirror-workspace

# Check current disk usage

    Quay-Based Mirror Registry Notes¶

    The mirror-registry installer uses Red Hat Quay as the backend, which has specific GC behavior:

    1. Tag deletion removes API-level references
    2. Manifest GC marks orphaned manifests (runs automatically)
    3. Blob GC deletes unused blobs (runs periodically)

    For Quay registries, expect: - GC happens automatically over 24-48 hours - Immediate space reclamation requires database-level cleanup (not recommended) - Disk usage may not decrease immediately after tag deletion

    Best Practice: Minimal Mirroring¶

    To minimize storage:

    # imageset-config.yaml - Keep only what you need
mirror:
  platform:
    channels:
      - name: stable-4.19
        minVersion: '4.19.20'   # Only latest patch
        maxVersion: '4.19.21'
        # Don't include old 4.18 channel after upgrade

    After upgrading to 4.19: 1. Remove 4.18 channel from imageset-config.yaml 2. Delete old operator catalog: oc delete catalogsource cs-redhat-operator-index-v4-18 -n openshift-marketplace 3. Run prune script (tags only - blobs will GC over time)

    Quay Auto-Prune Configuration¶

    The mirror-registry uses Red Hat Quay which supports automatic pruning of old tags.

    Enable auto-prune (already added during Phase 3 setup):

    # On mirror-registry VM
sudo tee -a /opt/quay/quay-config/config.yaml << 'EOF'

# Enable automatic pruning of old tags
FEATURE_AUTO_PRUNE: true
EOF

sudo podman restart quay-app

    Check Quay garbage collection status:

    kcli ssh mirror-registry "sudo podman logs quay-app 2>&1 | grep -i -E '(garbage|gc|prune)' | tail -20"

    Important Quay GC behavior: - Blob GC runs automatically in background (24-48 hour cycle) - Deleting manifests doesn't immediately free space - Shared blobs remain until ALL references are deleted - FEATURE_AUTO_PRUNE removes old tags automatically based on policies
