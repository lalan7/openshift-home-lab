    Phase 5: Create Systemd Service and Timer¶

    Date: December 2024
    Status: ✅ Completed

    Overview¶

    This phase creates systemd unit files for automated daily telemetry sync.

    Files Created¶

    File Purpose
    systemd/telemetry-sync.service Main sync service (gather + upload)
    systemd/telemetry-sync.timer Daily trigger at 03:00 UTC
    systemd/telemetry-retry.service Retry failed uploads
    systemd/telemetry-retry.timer Every 4 hours for retries
    scripts/install-systemd.sh Installation script

    Schedule¶

    Timer Schedule Purpose
    telemetry-sync.timer Daily 03:00 UTC Full sync (gather + upload)
    telemetry-retry.timer Every 4 hours Retry failed uploads

    Installation on homelab-server¶

    Prerequisites¶

    1. SSH to homelab-server as the user that will run the sync
    2. Ensure user lingering is enabled (for user services to run without login):
    # Check if lingering is enabled
loginctl show-user $USER | grep Linger

# Enable if needed (requires root)
sudo loginctl enable-linger $USER

    Installation Steps¶

    # 1. Clone or copy the repository to homelab-server
cd ~/sno-disconnected/telemetry-sync

# 2. Create configuration
cp config/telemetry-sync.env.template config/telemetry-sync.env

# 3. Edit configuration with your values
vi config/telemetry-sync.env

# 4. Run installer
./scripts/install-systemd.sh

    Configuration Required¶

    Before running the installer, set these values in config/telemetry-sync.env:

    # Cluster ID
CLUSTER_ID="your-cluster-id"

# Cloud token (from pull-secret)
CLOUD_TOKEN="your-token"

# Verify kubeconfig path
KUBECONFIG="${HOME}/sno-disconnected/auth/kubeconfig"

    To get CLUSTER_ID: 

    oc get clusterversion version -o jsonpath='{.spec.clusterID}'

    To get CLOUD_TOKEN: 

    oc extract secret/pull-secret -n openshift-config --to=- | jq -r '.auths["cloud.openshift.com"].auth'

    Unit File Details¶

    telemetry-sync.service¶

    [Service]
Type=oneshot
ExecStart=~/sno-disconnected/telemetry-sync/scripts/process-queue.sh
TimeoutStartSec=600    # 10 minutes max

    Key features: - Oneshot service (runs to completion) - 10-minute timeout - Logs to journald - Security hardening enabled

    telemetry-sync.timer¶

    [Timer]
OnCalendar=*-*-* 03:00:00 UTC
Persistent=true
RandomizedDelaySec=900

    Key features: - Runs at 03:00 UTC daily - Persistent=true: Runs immediately if missed (system was off) - Random delay up to 15 minutes

    Management Commands¶

    Timer Management¶

    # Check timer schedule
systemctl --user list-timers

# Check next run time
systemctl --user list-timers telemetry-sync.timer

# Start/stop timer
systemctl --user start telemetry-sync.timer
systemctl --user stop telemetry-sync.timer

# Enable/disable timer
systemctl --user enable telemetry-sync.timer
systemctl --user disable telemetry-sync.timer

    Service Management¶

    # Manual run
systemctl --user start telemetry-sync.service

# Check status
systemctl --user status telemetry-sync.service

# View logs
journalctl --user -u telemetry-sync.service -f

# View recent logs
journalctl --user -u telemetry-sync.service --since "1 hour ago"

    Retry Service¶

    # Manual retry of failed uploads
systemctl --user start telemetry-retry.service

# View retry logs
journalctl --user -u telemetry-retry.service -f

    Uninstallation¶

    ./scripts/install-systemd.sh --uninstall

    This will: 1. Stop timers 2. Disable timers 3. Remove unit files 4. Reload systemd daemon

    Troubleshooting¶

    Timer Not Running¶

    # Check if user lingering is enabled
loginctl show-user $USER | grep Linger
# Should show: Linger=yes

# If not, enable it
sudo loginctl enable-linger $USER

    Service Fails to Start¶

    # Check logs
journalctl --user -u telemetry-sync.service -e

# Run health check
~/sno-disconnected/telemetry-sync/scripts/health-check.sh

# Test manually
~/sno-disconnected/telemetry-sync/scripts/process-queue.sh

    Cannot Connect to Cluster¶

    # Verify kubeconfig
export KUBECONFIG=~/sno-disconnected/auth/kubeconfig
oc whoami
oc get nodes

    Logging¶

    Logs are written to: - journald: journalctl --user -u telemetry-sync.service - File logs: ${QUEUE_DIR}/logs/telemetry-sync.log
