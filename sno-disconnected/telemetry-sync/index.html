    SNO Disconnected Cluster - Telemetry Sync¶

    Purpose: Automated daily upload of Insights/Telemetry data from disconnected SNO cluster to Red Hat
    Created: December 2024
    Cluster: sno-disconnected.example.local (198.51.100.60)
    Management Host: homelab-server.example.com

    Overview¶

    This automation collects Insights Operator data from the disconnected SNO cluster and uploads it to Red Hat's console.redhat.com for analysis and support.

    Quick Start¶

    1. Configure¶

    cd ~/sno-disconnected/telemetry-sync/config/
cp telemetry-sync.env.template telemetry-sync.env

# Get required values
export KUBECONFIG=~/sno-disconnected/auth/kubeconfig

# Cluster ID
oc get clusterversion -o jsonpath='{.items[].spec.clusterID}'

# Cloud token (from pull-secret)
oc extract secret/pull-secret -n openshift-config --to=- 2>/dev/null | \
  jq -r '.auths["cloud.openshift.com"].auth'

# Edit config with your values
vim telemetry-sync.env

    2. Create Queue Directories¶

    source telemetry-sync.env
mkdir -p "${PENDING_DIR}" "${UPLOADED_DIR}" "${FAILED_DIR}" "${LOG_DIR}"

    3. Install Systemd Services¶

    # Copy service files
sudo cp systemd/*.service systemd/*.timer /etc/systemd/system/

# Reload and enable
sudo systemctl daemon-reload
sudo systemctl enable --now telemetry-sync.timer

# Verify timer is active
systemctl list-timers | grep telemetry

    4. Manual Test Run¶

    # Run gather + upload manually
./scripts/sync-telemetry.sh

# Check logs
tail -f ~/telemetry-queue/logs/telemetry-sync.log

    Configuration Reference¶

    Variable Description Default
    KUBECONFIG Path to cluster kubeconfig ~/sno-disconnected/auth/kubeconfig
    CLUSTER_ID Cluster UUID (required)
    CLOUD_TOKEN Auth token from pull-secret (required)
    QUEUE_DIR Base queue directory ~/telemetry-queue
    MAX_RETRIES Upload retry attempts 5
    RETRY_DELAYS Backoff delays (seconds) 60 300 900 3600 14400
    RETENTION_DAYS Keep uploaded archives 7
    LOG_LEVEL DEBUG, INFO, WARN, ERROR INFO
    ENABLE_OBFUSCATION Mask IPs/domains false

    See config/telemetry-sync.env.template for full configuration options.

    Scripts¶

    Script Purpose
    scripts/gather-insights.sh Collect Insights archive from cluster
    scripts/upload-insights.sh Upload single archive with retry
    scripts/process-queue.sh Process all pending archives
    scripts/health-check.sh Verify Red Hat API availability
    scripts/sync-telemetry.sh Main script: gather → upload → cleanup

    Systemd Services¶

    Unit Type Purpose
    telemetry-sync.timer Timer Triggers daily at 03:00 UTC
    telemetry-sync.service Service Main sync job
    telemetry-retry.service Service Retry failed uploads

    Queue Management¶

    Directory Structure¶

    ~/telemetry-queue/
├── pending/                    # Awaiting upload
│   └── insights-2024-12-12-030015.tar.gz
├── uploaded/                   # Successfully sent
│   └── insights-2024-12-11-030012.tar.gz
├── failed/                     # Max retries exceeded
│   └── insights-2024-12-10-030008.tar.gz.failed
└── logs/
    └── telemetry-sync.log

    Manual Queue Operations¶

    # View pending uploads
ls -la ~/telemetry-queue/pending/

# Retry a failed upload manually
mv ~/telemetry-queue/failed/insights-*.tar.gz.failed ~/telemetry-queue/pending/
./scripts/process-queue.sh

# Force immediate upload
./scripts/upload-insights.sh ~/telemetry-queue/pending/insights-*.tar.gz

# Clean old uploaded archives
find ~/telemetry-queue/uploaded/ -mtime +7 -delete

    Retry Logic¶

    The upload uses exponential backoff for reliability:

    Attempt Delay Cumulative Time
    1 Immediate 0
    2 1 minute 1 min
    3 5 minutes 6 min
    4 15 minutes 21 min
    5 1 hour 1h 21min
    6 (final) 4 hours 5h 21min

    If all retries fail, the archive moves to failed/ and an alert is logged.

    Indicator Good Warning Critical
    Pending queue 0-1 2-3 >3
    Failed queue 0 1-2 >2

    Troubleshooting¶

    Upload Fails with 401 Unauthorized¶

    # Token may have expired - refresh from pull-secret
oc extract secret/pull-secret -n openshift-config --to=- 2>/dev/null | \
  jq -r '.auths["cloud.openshift.com"].auth'

# Update telemetry-sync.env with new token
vim ~/sno-disconnected/telemetry-sync/config/telemetry-sync.env

    Cannot Connect to Cluster¶

    # Verify kubeconfig works
export KUBECONFIG=~/sno-disconnected/auth/kubeconfig
oc whoami
oc get nodes

# Check API reachability
curl -k https://api.sno-disconnected.example.local:6443/version

    Red Hat API Not Reachable¶

    # Test connectivity
./scripts/health-check.sh

# Manual test
curl -s https://console.redhat.com/api/ingress/v1/version

    Large Queue Backlog¶

    # Process queue immediately
./scripts/process-queue.sh

# Check for network issues
ping console.redhat.com
curl -I https://console.redhat.com

    Official Documentation Reference¶

    This implementation follows OCP 4.18 Documentation: Chapter 4.6 - Using Remote Health Reporting in a Restricted Network.

    Documentation Compliance¶

    Documentation Section Implementation
    4.6.1 Running an Insights Operator gather operation gather-insights.sh - copies archive from pod
    4.6.2 Uploading an Insights Operator archive upload-insights.sh - curl with multipart form
    4.6.3 Enabling Insights Operator data obfuscation Configurable via ENABLE_OBFUSCATION

    Upload Command (Per Documentation)¶

    The official procedure uses:

    curl -v \
  -H "User-Agent: insights-operator/... cluster/<cluster_id>" \
  -H "Authorization: Bearer <your_token>" \
  -F "upload=@<path_to_archive>; type=application/vnd.redhat.openshift.periodic+tar" \
  https://console.redhat.com/api/ingress/v1/upload

    Our implementation matches this exactly, with added: - Retry logic (5 attempts with exponential backoff) - Queue management (pending/uploaded/failed) - Automated daily execution via systemd - Comprehensive logging

    Token Extraction (Per Documentation)¶

    # Extract pull-secret
oc extract secret/pull-secret -n openshift-config --to=- | \
  jq -r '.auths["cloud.openshift.com"].auth'

    Future: DataGather CRD¶

    The DataGather CRD (for on-demand gathering) is currently Technology Preview in OCP 4.17-4.20. When it becomes GA, the gather script can be updated to use on-demand gathering instead of copying periodic archives.

    See: PHASE-DOCS/PHASE-06-testing.md for TODO item.

    Alerting (Future: Slack Integration)¶

    Slack webhook integration is documented in PHASE-DOCS/PHASE-06-slack.md for future implementation.

    To enable when ready:

    1. Create Slack incoming webhook
    2. Set SLACK_ENABLED="true" in config
    3. Set SLACK_WEBHOOK_URL with your webhook URL
    4. Alerts will trigger on:
    5. Upload failure after max retries
    6. Queue backlog > threshold
    7. Cluster connectivity issues
