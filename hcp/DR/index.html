    HCP Disaster Recovery¶

    Disaster Recovery implementation for Hosted Control Planes using OADP (OpenShift API for Data Protection).

    Overview¶

    This directory contains scripts, manifests, and runbooks for backing up and restoring hosted clusters.

    Quick Start¶

    1. Install OADP Operator¶

    ./scripts/01-install-oadp.sh

    2. Configure S3 Storage¶

    Choose one of the following options:

    Option A: ODF RGW (Recommended for homelab)¶

    Uses ODF's built-in Ceph RGW for S3-compatible storage. No external storage required.

    # Create bucket and credentials in one step
./scripts/setup-rgw-credentials.sh

# Deploy DataProtectionApplication
./scripts/deploy-dpa-rgw.sh

    Option B: External S3 (AWS, MinIO, etc.)¶

    Edit the credentials template:

    cp manifests/04-credentials-secret.yaml.template manifests/04-credentials-secret.yaml
# Edit with your S3 credentials
oc apply -f manifests/04-credentials-secret.yaml

    Deploy DPA:

    export S3_BUCKET="hcp-backups"
export S3_ENDPOINT="https://s3.example.com"
export S3_REGION="us-east-1"

envsubst < manifests/05-dpa.yaml.template | oc apply -f -

    4. Perform Backup¶

    ./scripts/02-backup-control-plane.sh <hosted-cluster-name> <namespace>

    5. Restore (if needed)¶

    # Same management cluster
./scripts/04-restore-same-cluster.sh <backup-name>

# New management cluster
./scripts/05-restore-new-cluster.sh <backup-name>

    Prerequisites¶

    • OADP Operator installed on management cluster
    • S3-compatible storage:
    • ODF RGW (recommended) - Built-in Ceph object storage, no external deps
    • ODF MCG (NooBaa)
    • MinIO
    • AWS S3
    • oc CLI with cluster-admin access
    • velero CLI (optional, for detailed status)

    Key Concepts¶

    What Gets Backed Up¶

    Component Description
    HostedCluster CR Cluster configuration
    HostedControlPlane CR Control plane settings
    NodePool CRs Worker node configuration
    Secrets Cluster secrets (pull-secret, SSH keys, etc.)
    ConfigMaps Configuration data
    etcd data Cluster state (via volume snapshots)
    ServiceAccounts RBAC identities
    Roles/RoleBindings RBAC permissions

    Restore Scenarios¶

    1. Same Management Cluster - Recover from data corruption
    2. New Management Cluster - Migrate or recover from total failure

    Important Notes¶

    • Data plane workloads continue running during management cluster issues
    • External DNS is required for cross-cluster restore
    • Always verify backups with ./scripts/verify-backup.sh
