    HCP Disaster Recovery Plan¶

    Document Information¶

    Field Value
    Version 1.0
    Last Updated 2025-01-09
    Owner SRE Team
    Review Frequency Quarterly

    1. Overview¶

    This document outlines the Disaster Recovery (DR) procedures for Hosted Control Planes (HCP) managed on OpenShift. It covers backup strategies, recovery procedures, and testing guidelines.

    1.1 Scope¶

    • Hosted clusters managed by HyperShift
    • Management cluster protection
    • etcd data and cluster configuration

    1.2 Out of Scope¶

    • Application-level DR (covered separately per application)
    • Infrastructure-level DR (covered by infrastructure team)

    2. Recovery Objectives¶

    Metric Target Notes
    RPO (Recovery Point Objective) 24 hours Daily backups at 02:00 UTC
    RTO (Recovery Time Objective) 4 hours Time to restore hosted cluster
    MTTR (Mean Time To Recovery) 2 hours Average recovery time

    3. Disaster Scenarios¶

    3.1 Scenario Classification¶

    Scenario Severity Impact Recovery Method
    Single etcd pod failure Low None (auto-recovery) Automatic
    etcd quorum loss Medium Control plane unavailable etcd restore
    Management cluster degraded Medium Cannot modify clusters Wait/troubleshoot
    Management cluster total loss High Cannot manage clusters Cross-cluster restore
    Hosted cluster data corruption High Cluster unusable Full restore

    3.2 Impact Matrix¶

    Component Failed Control Plane Data Plane (Workloads)
    Management API Degraded No impact
    etcd Unavailable No impact
    HyperShift Operator Cannot modify No impact
    Entire Management Cluster Unavailable No impact

    Key Point: Data plane workloads continue running even during management cluster failures.

    4. Backup Strategy¶

    4.1 What Gets Backed Up¶

    Resource Backup Method Frequency
    HostedCluster CR OADP Daily
    HostedControlPlane CR OADP Daily
    NodePool CRs OADP Daily
    Secrets OADP Daily
    ConfigMaps OADP Daily
    etcd data CSI Volume Snapshot Daily
    RBAC resources OADP Daily

    4.2 Backup Schedule¶

    Daily:    02:00 UTC - Full control plane backup
Weekly:   Sunday 03:00 UTC - Extended backup with additional validation
Monthly:  1st Sunday 04:00 UTC - Long-term retention backup (90 days)

    4.3 Retention Policy¶

    Backup Type Retention
    Daily 7 days
    Weekly 4 weeks
    Monthly 90 days
    Pre-upgrade Until next successful upgrade

    4.4 Storage Requirements¶

    • S3-compatible storage (MinIO, ODF MCG, AWS S3)
    • Minimum 100GB per hosted cluster
    • Geo-redundant storage recommended

    5. Recovery Procedures¶

    5.1 Decision Tree¶

                     │  Incident Detected  │
                     └──────────┬──────────┘
                                │
                     ┌──────────▼──────────┐
                     │ Management Cluster  │
                     │    Accessible?      │
                     └──────────┬──────────┘

                    ┌───────┘      └────────┐
                    ▼                       ▼
         ┌──────────────────┐    ┌──────────────────┐

         └────────┬─────────┘    │ Cluster          │
            Yes │    │ No        └──────────────────┘

          ▼                ▼
┌─────────────────┐  ┌─────────────────┐

└─────────────────┘  └─────────────────┘

    5.2 Procedure: Restore to Same Management Cluster¶

    When to use: Data corruption, accidental deletion, rollback needed

    Estimated time: 30-60 minutes

    1. Verify backup integrity 

      ./scripts/verify-backup.sh <backup-name>

    2. Pause cluster reconciliation (if not already paused) 

      oc patch hostedcluster <name> -n <ns> --type=merge \
  -p '{"spec":{"pausedUntil":"true"}}'

    3. Execute restore 

      ./scripts/04-restore-same-cluster.sh <backup-name>

    4. Resume reconciliation 

      oc patch hostedcluster <name> -n <ns> --type=merge \
  -p '{"spec":{"pausedUntil":null}}'

    5. Verify cluster health 

      oc get hostedcluster -A
oc get nodepool -A

    5.3 Procedure: Restore to New Management Cluster¶

    When to use: Management cluster unrecoverable, migration required

    Estimated time: 2-4 hours

    Prerequisites: - New management cluster with HyperShift Operator - OADP configured with same S3 storage - External DNS configured

    1. Prepare new management cluster 

      # Install OADP
./scripts/01-install-oadp.sh

# Configure same S3 backend
# (use same credentials and bucket)

    2. Verify backup is accessible 

      ./scripts/verify-backup.sh <backup-name>

    3. Execute cross-cluster restore 

      ./scripts/05-restore-new-cluster.sh <backup-name>

    4. Resume hosted cluster reconciliation 

      oc patch hostedcluster <name> -n <ns> --type=merge \
  -p '{"spec":{"pausedUntil":null}}'

    5. Delete resources from old cluster (if accessible) 

      # On OLD management cluster
oc delete hostedcluster <name> -n <ns>

    6. Roles and Responsibilities¶

    Role Responsibilities
    On-Call SRE Initial response, severity assessment
    HCP Team Lead Escalation point, recovery authorization
    Infrastructure Team S3/storage issues, network connectivity
    Platform Team Management cluster issues

    7. Communication Plan¶

    7.1 Escalation Matrix¶

    Severity Response Time Escalation
    Critical 15 minutes Immediate page to HCP Team
    High 30 minutes Page during business hours
    Medium 4 hours Ticket, no page
    Low Next business day Ticket

    7.2 Notification Channels¶

    • Primary: #hcp-incidents Slack channel
    • Secondary: PagerDuty
    • Stakeholders: Email distribution list

    8. Testing Requirements¶

    8.1 Test Schedule¶

    Test Type Frequency Last Tested Next Due
    Backup verification Weekly - -
    Same-cluster restore Monthly - -
    Cross-cluster restore Quarterly - -
    Full DR drill Annually - -

    8.2 Test Procedure¶

    1. Create test hosted cluster
    2. Deploy sample workload
    3. Take backup
    4. Corrupt or delete cluster
    5. Execute restore
    6. Verify workload restored
    7. Document results

    9. Appendix¶

    9.1 Quick Reference Commands¶

    # List all backups
oc get backup -n openshift-adp

# Check backup status
./scripts/verify-backup.sh <backup-name>

# Manual backup
./scripts/02-backup-control-plane.sh <cluster-name> <namespace>

# Restore
./scripts/04-restore-same-cluster.sh <backup-name>

# Check hosted cluster health
oc get hostedcluster -A -o wide
oc get nodepool -A -o wide
