    HCP Restore Procedures¶

    Step-by-step restore procedures for Hosted Control Planes.

    Prerequisites¶

    • Backup verified and accessible
    • oc CLI installed and authenticated as cluster-admin
    • OADP Operator installed and configured
    • For cross-cluster restore: New management cluster prepared

    Verify Prerequisites¶

    # Check OADP status
oc get dpa -n openshift-adp

# Verify backup exists
./scripts/verify-backup.sh <backup-name>

    Procedure 1: Restore to Same Management Cluster¶

    Use when: Data corruption, accidental deletion, rollback to previous state

    Estimated time: 30-60 minutes

    Step 1: Assess the Situation¶

    Document: - What happened: __ - Which cluster affected: __ - When did it occur: __ - Is the hosted cluster accessible: __

    Step 2: Select Backup to Restore¶

    # List available backups
./scripts/verify-backup.sh

# Verify the backup you want to restore
./scripts/verify-backup.sh <backup-name>

    Record: - Backup Name: __ - Backup Date: __ - Backup Status: ___

    Step 3: Pause Reconciliation (If Not Already)¶

    # Pause HostedCluster
oc patch hostedcluster <name> -n <namespace> --type=merge \
  -p '{"spec":{"pausedUntil":"true"}}'

# Pause NodePools
oc patch nodepool <name> -n <namespace> --type=merge \
  -p '{"spec":{"pausedUntil":"true"}}'

    Step 4: Execute Restore¶

    ./scripts/04-restore-same-cluster.sh <backup-name>

    The script will: 1. Verify backup exists and is completed 2. Show backup details 3. Ask for confirmation 4. Create Restore CR 5. Wait for completion

    Step 5: Monitor Restore Progress¶

    # Watch restore status
oc get restore -n openshift-adp -w

# Get detailed status
oc describe restore restore-<backup-name>-<timestamp> -n openshift-adp

    Step 6: Verify Restore Completion¶

    Check restore status: 

    oc get restore -n openshift-adp

    Expected: Phase: Completed

    Step 7: Resume Reconciliation¶

    # Resume HostedCluster
oc patch hostedcluster <name> -n <namespace> --type=merge \
  -p '{"spec":{"pausedUntil":null}}'

# Resume NodePools
oc patch nodepool <name> -n <namespace> --type=merge \
  -p '{"spec":{"pausedUntil":null}}'

    Step 8: Verify Cluster Health¶

    # Check HostedCluster status
oc get hostedcluster <name> -n <namespace> -o wide

# Verify Available=True
oc get hostedcluster <name> -n <namespace> \
  -o jsonpath='{.status.conditions[?(@.type=="Available")].status}'

# Check NodePool
oc get nodepool -n <namespace>

# Check control plane pods
oc get pods -n <namespace>-<cluster-name>

    Step 9: Verify Worker Nodes¶

    # Get hosted cluster kubeconfig
oc get secret <name>-admin-kubeconfig -n <namespace> \
  -o jsonpath='{.data.kubeconfig}' | base64 -d > /tmp/hc-kubeconfig

# Check nodes on hosted cluster
KUBECONFIG=/tmp/hc-kubeconfig oc get nodes

    Step 10: Document Recovery¶

    Record: - Recovery Date/Time: __ - Backup Used: __ - Restore Name: __ - Duration: __ - Issues Encountered: __ - Operator: __

    Procedure 2: Restore to New Management Cluster¶

    Use when: Original management cluster is unrecoverable, migration required

    Estimated time: 2-4 hours

    Step 1: Prepare New Management Cluster¶

    Ensure the new cluster has: - [ ] OpenShift 4.14+ installed - [ ] HyperShift Operator installed - [ ] Network connectivity to worker nodes - [ ] External DNS configured (if using)

    Step 2: Install OADP on New Cluster¶

    # On NEW management cluster
./scripts/01-install-oadp.sh

    Step 3: Configure Same S3 Backend¶

    Use the same S3 credentials and bucket as the source cluster:

    # Apply credentials secret (same values as source)
oc apply -f manifests/04-credentials-secret.yaml

# Apply DPA with same S3 configuration
export S3_BUCKET="<same-bucket>"
export S3_ENDPOINT="<same-endpoint>"
export S3_REGION="<same-region>"
envsubst < manifests/05-dpa.yaml.template | oc apply -f -

    Step 4: Wait for Backup Sync¶

    # Wait for OADP to sync backups from S3
oc wait --for=jsonpath='{.status.phase}'=Available \
  backupstoragelocation/default -n openshift-adp --timeout=300s

# Verify backup is visible
./scripts/verify-backup.sh <backup-name>

    Step 5: Execute Cross-Cluster Restore¶

    ./scripts/05-restore-new-cluster.sh <backup-name>

    Step 6: Monitor Restore¶

    oc get restore -n openshift-adp -w

    Step 7: Resume Reconciliation on New Cluster¶

    # Resume HostedCluster
oc patch hostedcluster <name> -n <namespace> --type=merge \
  -p '{"spec":{"pausedUntil":null}}'

# Resume NodePools
oc patch nodepool <name> -n <namespace> --type=merge \
  -p '{"spec":{"pausedUntil":null}}'

    Step 8: Verify Control Plane Starts¶

    # Watch control plane pods come up
oc get pods -n <namespace>-<cluster-name> -w

# Check HostedCluster becomes Available
oc get hostedcluster <name> -n <namespace> -w

    Step 9: Update DNS (If Using External DNS)¶

    If using external DNS, it should automatically update. Verify:

    # Check DNS resolution
dig api.<cluster-name>.<base-domain>

# Should resolve to new cluster's ingress

    Step 10: Clean Up Old Cluster (If Accessible)¶

    IMPORTANT: Only do this AFTER verifying the restore is successful!

    # On OLD management cluster (if accessible)
oc delete hostedcluster <name> -n <namespace> --wait=false

# Force delete if stuck
oc patch hostedcluster <name> -n <namespace> \
  --type=merge -p '{"metadata":{"finalizers":[]}}'

    Step 11: Document Recovery¶

    Record: - Source Cluster: __ - Destination Cluster: __ - Backup Used: __ - Recovery Time: __ - Issues Encountered: ___

    Troubleshooting¶

    Restore Stuck in "InProgress"¶

    # Check restore details
oc describe restore <restore-name> -n openshift-adp

# Check velero logs
oc logs -n openshift-adp -l app.kubernetes.io/name=velero

# Check for PVC restore issues
oc get pvc -n <control-plane-namespace>

    Restore Failed¶

    # Get failure reason
oc get restore <restore-name> -n openshift-adp \
  -o jsonpath='{.status.failureReason}'

# Check detailed logs
velero restore logs <restore-name>

    HostedCluster Not Becoming Available¶

    # Check HostedCluster conditions
oc get hostedcluster <name> -n <namespace> -o yaml

# Check control plane pods
oc get pods -n <namespace>-<cluster-name>

# Check etcd logs
oc logs -n <namespace>-<cluster-name> -l app=etcd

    Workers Not Joining¶

    # Check NodePool status
oc get nodepool <name> -n <namespace> -o yaml

# Check agent machines
oc get agentmachine -n <namespace>-<cluster-name>

# On hosted cluster, check nodes
KUBECONFIG=/tmp/hc-kubeconfig oc get nodes
KUBECONFIG=/tmp/hc-kubeconfig oc get csr

    Conflict with Old Cluster¶

    If both clusters try to manage the same hosted cluster:

    1. Stop reconciliation on old cluster immediately: 

      # On OLD cluster
oc patch hostedcluster <name> -n <namespace> --type=merge \
  -p '{"spec":{"pausedUntil":"true"}}'

    2. Delete from old cluster: 

      oc delete hostedcluster <name> -n <namespace>

    Rollback Procedures¶

    If Restore Fails Mid-Way¶

    1. Delete partial restore resources: 

      oc delete restore <restore-name> -n openshift-adp

    2. Clean up any partially restored resources: 

      oc delete hostedcluster <name> -n <namespace> --ignore-not-found
oc delete namespace <namespace>-<cluster-name> --ignore-not-found

    3. Try restore again with different backup if available

    Quick Reference¶

    Command Description
    ./scripts/04-restore-same-cluster.sh <backup> Restore to same cluster
    ./scripts/05-restore-new-cluster.sh <backup> Restore to new cluster
    oc get restore -n openshift-adp List restores
    oc describe restore <name> -n openshift-adp Restore details
    velero restore logs <name> Restore logs
