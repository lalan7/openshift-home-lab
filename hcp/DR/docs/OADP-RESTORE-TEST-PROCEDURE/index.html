    OADP HCP Restore Test Procedure¶

    Date: 2026-01-19
    Cluster: management-hypershift-lab
    Hosted Cluster: sno-hcp
    Control Plane Namespace: clusters-sno-hcp

    ⚠️ Note: This procedure was tested with SingleReplica etcd (1 pod). The HighlyAvailable (3 etcd) commands are documented but not yet tested. The same principles apply, but with 3 PVCs and 3 pods.

    Overview¶

    This document provides a step-by-step procedure to test OADP restore of the HCP control plane, including etcd data recovery.

    Prerequisites¶

    • OADP installed and configured
    • Valid backup exists with etcd data
    • oc CLI with cluster-admin access
    • Hosted cluster kubeconfig available

    Verify Prerequisites¶

    # Check OADP is ready
oc get dpa -n openshift-adp
oc get backupstoragelocation -n openshift-adp

# List available backups
oc get backup -n openshift-adp

# Verify backup includes etcd data (DataUpload completed)
oc get dataupload -n openshift-adp -l velero.io/backup-name=<backup-name>

    Understanding OADP HCP Restore¶

    What OADP Backs Up¶

    Component Location Backup Method
    HostedCluster CR clusters namespace K8s resource
    NodePool CR clusters namespace K8s resource
    Secrets clusters + control plane namespace K8s resource
    ConfigMaps clusters + control plane namespace K8s resource
    etcd PVC (data-etcd-0) clusters-sno-hcp CSI Snapshot → S3

    Key Insight: etcd Data¶

    The etcd PVC contains all hosted cluster data: - Namespaces - Deployments - ConfigMaps - Secrets - All Kubernetes resources in the hosted cluster

    When you restore the etcd PVC, you restore the entire hosted cluster state.

    Why Simple Restore Doesn't Work¶

    A restore with existingResourcePolicy: update: - Updates K8s resources on management cluster ✅ - Restores etcd PVC data to the volume ✅ - BUT: Running etcd pod doesn't reload the restored data ❌

    The etcd pod has the data in memory and on its mounted volume. The restored data is written to the volume, but etcd doesn't know to reload it.

    Proper Restore Procedure¶

    To properly restore etcd data: 1. Scale down etcd (stop the pod) 2. Delete the etcd PVC (remove current data) 3. Run OADP restore (recreates PVC with backup data) 4. Scale up etcd (pod starts with restored data)

    Test Procedure: Full etcd Restore Test¶

    Phase 1: Create Test Data¶

    Create a marker in the hosted cluster that we can verify after restore.

    # Extract hosted cluster kubeconfig
oc get secret sno-hcp-admin-kubeconfig -n clusters \
  -o jsonpath='{.data.kubeconfig}' | base64 -d > /tmp/sno-hcp-kubeconfig

# Create test ConfigMap in hosted cluster
KUBECONFIG=/tmp/sno-hcp-kubeconfig oc create configmap oadp-restore-test \
  -n default \
  --from-literal=test-key="restore-test-$(date +%Y%m%d-%H%M%S)" \
  --from-literal=created="$(date)" \
  --from-literal=purpose="OADP restore verification"

# Verify it was created
KUBECONFIG=/tmp/sno-hcp-kubeconfig oc get configmap oadp-restore-test -n default -o yaml

    Record the test-key value: restore-test-YYYYMMDD-HHMMSS

    Phase 2: Take Backup with Test Data¶

    cd ~/Documents/code/MYHOMELAB/hcp/DR

# Take backup (includes the test ConfigMap in etcd)
./scripts/02-backup-control-plane.sh sno-hcp clusters

    Wait for backup to complete: 

    # Watch backup progress
oc get backup -n openshift-adp -w

# Record backup name: hcp-sno-hcp-YYYYMMDD-HHMMSS

    Verify etcd data was captured: 

    # Check DataUpload completed (should show ~400MB for etcd)
oc get dataupload -n openshift-adp -l velero.io/backup-name=<backup-name>

    Resume reconciliation: 

    oc patch hostedcluster sno-hcp -n clusters --type=merge -p '{"spec":{"pausedUntil":null}}'

    Phase 3: Delete Test Data (Simulate Corruption)¶

    # Delete the test ConfigMap from hosted cluster
KUBECONFIG=/tmp/sno-hcp-kubeconfig oc delete configmap oadp-restore-test -n default

# Verify it's gone
KUBECONFIG=/tmp/sno-hcp-kubeconfig oc get configmap oadp-restore-test -n default
# Expected: Error from server (NotFound)

    Phase 4: Perform etcd Restore¶

    This is the critical phase where we restore the etcd data.

    export CONTROL_PLANE_NAMESPACE="clusters-sno-hcp"
export BACKUP_NAME="hcp-sno-hcp-YYYYMMDD-HHMMSS"  # Use your actual backup name

    Determine etcd Replica Count¶

    First, check your HCP availability policy to determine etcd replica count:

    # Check HostedCluster availability policy
oc get hostedcluster sno-hcp -n clusters -o jsonpath='{.spec.controllerAvailabilityPolicy}'
    Policy etcd Replicas PVCs to Delete
    SingleReplica 1 data-etcd-0
    HighlyAvailable 3 data-etcd-0, data-etcd-1, data-etcd-2 
    # Get current replica count
ETCD_REPLICAS=$(oc get statefulset etcd -n $CONTROL_PLANE_NAMESPACE -o jsonpath='{.spec.replicas}')
echo "etcd replicas: $ETCD_REPLICAS"

    Step 4.1: Pause HostedCluster¶

    oc patch hostedcluster sno-hcp -n clusters --type=merge \
  -p '{"spec":{"pausedUntil":"true"}}'

# Verify
oc get hostedcluster sno-hcp -n clusters -o jsonpath='{.spec.pausedUntil}'
# Should show: true

    Step 4.2: Scale Down etcd¶

    For SingleReplica (1 etcd): 

    # Scale etcd to 0
oc scale -n $CONTROL_PLANE_NAMESPACE statefulset/etcd --replicas=0

# Wait for etcd pod to terminate
oc wait --for=delete pod/etcd-0 -n $CONTROL_PLANE_NAMESPACE --timeout=120s

# Verify no etcd pods
oc get pods -n $CONTROL_PLANE_NAMESPACE -l app=etcd
# Should show: No resources found

    For HighlyAvailable (3 etcd): (not tested) 

    # Scale etcd to 0
oc scale -n $CONTROL_PLANE_NAMESPACE statefulset/etcd --replicas=0

# Wait for all etcd pods to terminate
oc wait --for=delete pod/etcd-0 pod/etcd-1 pod/etcd-2 \
  -n $CONTROL_PLANE_NAMESPACE --timeout=120s

# Verify no etcd pods
oc get pods -n $CONTROL_PLANE_NAMESPACE -l app=etcd
# Should show: No resources found

    ⚠️ At this point, the hosted cluster API is DOWN. This is expected.

    Step 4.3: Delete etcd PVC(s)¶

    For SingleReplica (1 etcd): 

    # Delete the etcd PVC
oc delete pvc data-etcd-0 -n $CONTROL_PLANE_NAMESPACE

# Wait for deletion
oc get pvc -n $CONTROL_PLANE_NAMESPACE | grep etcd
# Should show nothing

    For HighlyAvailable (3 etcd): (not tested) 

    # Delete all etcd PVCs
oc delete pvc data-etcd-0 data-etcd-1 data-etcd-2 -n $CONTROL_PLANE_NAMESPACE

# Wait for deletion
oc get pvc -n $CONTROL_PLANE_NAMESPACE | grep etcd
# Should show nothing

    Step 4.4: Run OADP Restore¶

    cd ~/Documents/code/MYHOMELAB/hcp/DR

# Run restore script
./scripts/04-restore-same-cluster.sh $BACKUP_NAME

# When prompted, type 'yes' to confirm

    Monitor restore progress: 

    # Watch restore status
oc get restore -n openshift-adp -w

# Check for DataDownload (etcd data being restored)
oc get datadownload -n openshift-adp

    Wait for restore to complete (Phase: Completed)

    Step 4.5: Verify PVC is Restored¶

    # Check etcd PVC exists
oc get pvc data-etcd-0 -n $CONTROL_PLANE_NAMESPACE

# Expected: Bound status

    Step 4.6: Scale Up etcd¶

    For SingleReplica (1 etcd): 

    # Scale etcd back up to 1
oc scale -n $CONTROL_PLANE_NAMESPACE statefulset/etcd --replicas=1

# Wait for etcd to be ready
oc wait --for=condition=Ready pod/etcd-0 -n $CONTROL_PLANE_NAMESPACE --timeout=300s

# Verify etcd is running
oc get pods -n $CONTROL_PLANE_NAMESPACE -l app=etcd

    For HighlyAvailable (3 etcd): (not tested) 

    # Scale etcd back up to 3
oc scale -n $CONTROL_PLANE_NAMESPACE statefulset/etcd --replicas=3

# Wait for all etcd pods to be ready
oc wait --for=condition=Ready pod/etcd-0 pod/etcd-1 pod/etcd-2 \
  -n $CONTROL_PLANE_NAMESPACE --timeout=300s

# Verify all etcd pods are running
oc get pods -n $CONTROL_PLANE_NAMESPACE -l app=etcd
# Should show: etcd-0, etcd-1, etcd-2 all Running

# Verify etcd cluster health
oc rsh -n $CONTROL_PLANE_NAMESPACE -c etcd etcd-0 etcdctl endpoint health --cluster

    Step 4.7: Resume HostedCluster¶

    oc patch hostedcluster sno-hcp -n clusters --type=merge \
  -p '{"spec":{"pausedUntil":null}}'

# Wait for HostedCluster to become available
oc get hostedcluster sno-hcp -n clusters -w

    Phase 5: Verify Restore¶

    5.1: Check HostedCluster Health¶

    oc get hostedcluster sno-hcp -n clusters

# Expected: Available=True

    5.2: Check Control Plane Pods¶

    oc get pods -n $CONTROL_PLANE_NAMESPACE

# All pods should be Running

    5.3: Verify Test Data is Restored¶

    # Re-extract kubeconfig (may have been refreshed)
oc get secret sno-hcp-admin-kubeconfig -n clusters \
  -o jsonpath='{.data.kubeconfig}' | base64 -d > /tmp/sno-hcp-kubeconfig

# Check if ConfigMap is back
KUBECONFIG=/tmp/sno-hcp-kubeconfig oc get configmap oadp-restore-test -n default

# View the restored data
KUBECONFIG=/tmp/sno-hcp-kubeconfig oc get configmap oadp-restore-test -n default -o yaml

    Expected output: 

    apiVersion: v1
data:
  created: Mon Jan 19 13:53:06 EST 2026
  purpose: OADP restore verification
  test-key: restore-test-20260119-135306  # Should match original value
kind: ConfigMap
metadata:
  name: oadp-restore-test
  namespace: default

    If the ConfigMap is back with the original values, the restore was successful!

    Phase 6: Cleanup¶

    # Delete test ConfigMap
KUBECONFIG=/tmp/sno-hcp-kubeconfig oc delete configmap oadp-restore-test -n default

# Clean up kubeconfig
rm /tmp/sno-hcp-kubeconfig

    Quick Reference¶

    Environment Variables¶

    export CONTROL_PLANE_NAMESPACE="clusters-sno-hcp"
export BACKUP_NAME="hcp-sno-hcp-YYYYMMDD-HHMMSS"

# Get current etcd replica count
ETCD_REPLICAS=$(oc get statefulset etcd -n $CONTROL_PLANE_NAMESPACE -o jsonpath='{.spec.replicas}')

    Commands Summary - SingleReplica (1 etcd)¶

    Step Command
    Pause HCP oc patch hostedcluster sno-hcp -n clusters --type=merge -p '{"spec":{"pausedUntil":"true"}}'
    Scale down etcd oc scale -n $CONTROL_PLANE_NAMESPACE statefulset/etcd --replicas=0
    Wait for etcd oc wait --for=delete pod/etcd-0 -n $CONTROL_PLANE_NAMESPACE --timeout=120s
    Delete PVC oc delete pvc data-etcd-0 -n $CONTROL_PLANE_NAMESPACE
    Run restore ./scripts/04-restore-same-cluster.sh $BACKUP_NAME
    Scale up etcd oc scale -n $CONTROL_PLANE_NAMESPACE statefulset/etcd --replicas=1
    Wait for etcd oc wait --for=condition=Ready pod/etcd-0 -n $CONTROL_PLANE_NAMESPACE --timeout=300s
    Resume HCP oc patch hostedcluster sno-hcp -n clusters --type=merge -p '{"spec":{"pausedUntil":null}}'

    Commands Summary - HighlyAvailable (3 etcd) ⚠️ NOT TESTED¶

    Step Command
    Pause HCP oc patch hostedcluster <name> -n clusters --type=merge -p '{"spec":{"pausedUntil":"true"}}'
    Scale down etcd oc scale -n $CONTROL_PLANE_NAMESPACE statefulset/etcd --replicas=0
    Wait for etcd oc wait --for=delete pod/etcd-0 pod/etcd-1 pod/etcd-2 -n $CONTROL_PLANE_NAMESPACE --timeout=120s
    Delete PVCs oc delete pvc data-etcd-0 data-etcd-1 data-etcd-2 -n $CONTROL_PLANE_NAMESPACE
    Run restore ./scripts/04-restore-same-cluster.sh $BACKUP_NAME
    Scale up etcd oc scale -n $CONTROL_PLANE_NAMESPACE statefulset/etcd --replicas=3
    Wait for etcd oc wait --for=condition=Ready pod/etcd-0 pod/etcd-1 pod/etcd-2 -n $CONTROL_PLANE_NAMESPACE --timeout=300s
    Verify health oc rsh -n $CONTROL_PLANE_NAMESPACE -c etcd etcd-0 etcdctl endpoint health --cluster
    Resume HCP oc patch hostedcluster <name> -n clusters --type=merge -p '{"spec":{"pausedUntil":null}}'

    etcd Replica Configuration Reference¶

    HostedCluster Setting etcd Replicas Use Case
    controllerAvailabilityPolicy: SingleReplica 1 Development, SNO, resource-constrained
    controllerAvailabilityPolicy: HighlyAvailable 3 Production, requires 3+ nodes

    Troubleshooting¶

    etcd Pod Not Starting After Restore¶

    # Check etcd pod status
oc describe pod etcd-0 -n $CONTROL_PLANE_NAMESPACE

# Check etcd logs
oc logs -n $CONTROL_PLANE_NAMESPACE etcd-0 -c etcd

# Check PVC is mounted
oc get pvc data-etcd-0 -n $CONTROL_PLANE_NAMESPACE

    Restore Stuck in InProgress¶

    # Check restore details
oc describe restore <restore-name> -n openshift-adp

# Check DataDownload status
oc get datadownload -n openshift-adp

# Check node-agent logs
oc logs -n openshift-adp -l app.kubernetes.io/name=node-agent --tail=100

    HostedCluster Not Becoming Available¶

    # Check HostedCluster conditions
oc get hostedcluster sno-hcp -n clusters -o yaml | grep -A20 conditions

# Check all control plane pods
oc get pods -n $CONTROL_PLANE_NAMESPACE

# Check kube-apiserver logs
oc logs -n $CONTROL_PLANE_NAMESPACE -l app=kube-apiserver --tail=50
